# 上游 v1.0.6 四大模块移植计划（本地 v1.0.27 → v1.0.28）

## Context

上游 ArrogHie/ControlECO v1.0.6 相对 v1.0.5 的四项改进（支付宝识别、悬浮窗可靠性、商户归类、退款统一）本地 v1.0.27 均未包含。用户要求全部移植，并评估本地逻辑调整与风险。两仓库历史无关，本地功能更新（DB v21 vs 上游 14），**只能逐块适配，不能整文件替换**。

### 已核实的关键事实

- 上游 v1.0.5→v1.0.6 **无 Room schema 变化**（DB version 保持 14，Entities.kt 仅注释改动）；本地 DB v21 同样**无需新增迁移**。
- 与上游 v1.0.5 基线**完全一致、可直接套 diff** 的本地文件：`OverlayComposeHost.kt`、`MerchantRules.kt`、`CaptureDefaults.kt`、`AlipayPageParser.kt`、`CategoryGuesser.kt`。
- 需**手工适配**（本地已偏离基线）：`NotificationRules.kt`、`ConfirmCardWindow.kt`、`ConfirmCardContent.kt`、`OverlayDecision.kt`、`PendingActions.kt`、`CaptureCenter.kt`、`PendingScreen.kt`、`LedgerViewModel.kt`、`RefundLinkScreen.kt`、`AppNav.kt`。
- **必须保留的本地修复**：①同应用去重要求"通道实例身份相同"（LogicalTransactions.kt L325-334）；②`absorbedByExisting` 在直接入账之后（CaptureCenter 三通道）；③分类筛选改造、帮助 UI、退款差额统计等本地扩展。
- 上游源码位于 /tmp/upstream-eco（tag v1.0.5/v1.0.6），移植时逐块参照 `git diff v1.0.5..v1.0.6`。

## 模块 A：支付宝识别（风险：低）

1. `NotificationRules.kt`：新增 `alipayPointsExpense` 正则与 `parseAlipayPointsExpense()`，在 parse() 的 `body.isBlank` 之后、微信身份闸门之前插入调用（本地 L456 附近，手工定位插入点）；无金额退款日志文案同步。
2. `AlipayPageParser.kt`（基线一致，直接套 diff）：成功页判定改 `lines.take(2)` 任一节点以"支付成功"开头；`firstPaymentAmount(lines, successIndex)` 从锚点起取金额。
3. 移植测试：`NotificationRulesTest`（积分模板）、`PaymentPageParserTest`（第二节点版式）。

## 模块 B：悬浮窗可靠性（风险：中）

1. `ConfirmCardWindow.kt`（手工适配）：`addView` 前注册 `OnDrawListener`，**首帧绘制才 `OverlayPromptLog.markShown`**；addView 成功仅记 attached。本地 recorded strip/top strip 两处不动。
2. `CaptureCenter.tryShowConfirmCard`：延迟后 `repeat(3)` 重试（间隔 1s），保留本地 `shownCardIds` 与 dedupKey 预检；`showCardOnMain` 在 addView 后 500ms 检查首帧：未绘制则 `dismissConfirm` 并 resume(false)，已绘制才取消兜底通知。
3. `OverlayComposeHost.kt`（基线一致）：init 中 `performRestore(null)` + CREATED，attach 仅 RESUMED。
4. `OverlayDecision.kt`（手工适配）：新增 `foregroundAfterEvent`；`noteForegroundPackage` 接入；`setAppForeground(false)`/`markA11yConnected(false)` 清前台包名。
5. 移植 `ConfirmCardStateTest` 新增用例；验证 announceEntry 回落通知时序不变。

## 模块 C：商户归类（风险：中）

1. `MerchantRules.kt`（基线一致，直接套 diff）：keyOf 重写（NFKC、标签/渠道前缀剥离、金额与换行拒绝、stopWords 扩充、平台商户只认备注标注）；match 兼容历史带标签/全角键。
2. `CaptureDefaults.kt`（基线一致）：拆出 `categorySuggestionId`（无证据返回 null，不降级"其他"；收入兜底排除"退款"分类）。
3. `ConfirmCardContent.kt`（手工适配）：富化时 `!categoryUserEdited` 才用 `categorySuggestionId` 刷新建议；账户填充加 `learnedAccountId`。
4. `CaptureCenter`：新增 `syncAutoEntryCategory()`，在通知/页面两处富化后调用（尊重 userEdited、GuardedField.CATEGORY、退款除外）；`enterEntry` 保留现有兜底分类逻辑。
5. DAO：`updateCategory`、merchant_rules 查询去 LIMIT 300。
6. 移植 `MerchantRulesTest`、`CaptureDefaultsTest`、`CategoryGuesserTest` 新增用例。

## 模块 D：退款统一（风险：高，行为口径变化）

**采用上游口径**：带金额退款也先入待处理，选中原支出才记收入；移除"记为收入"入口；旧版已入账 `refundPending=1` 收入走兼容路径，不重复生成收入。

1. 基础层：新增 `capture/RefundCapture.kt`（canDirectlyEnterCapture / canFillRefundAmount / refundNoticePending）、`data/RefundActions.kt`（refundExpense / refundCaptured / handleLegacyRefund / undoRefund，全事务化，markResolved/forget 配对）、`data/RefundRules.kt`、`ui/refund/RefundFilters.kt`；`LogicalTransactions` 新增 `findResolvedByKey`；DAO 新增 `refundCandidates(amountCents?)`、`clearExpenseRefund`、`firstRefundIncomeAfter`，退役 `markRefundAsIncome`。
2. 捕获层（CaptureCenter）：
   - `enterEntry` 入口加 `canDirectlyEnterCapture` 闸门 → 退款走 pending + announceCapture 路径；普通交易保持"先入账后并入"本地修复不变。
   - `handleRefundNotice` 改为落库 0 元 pending（已处理判定：findIdByExternalId + findResolvedByKey），`postRefundNotification` 路由 `refundLink/{pendingId}` 带 ignoreAction。
   - 通知 `sameInstance` 分支：`canFillRefundAmount` 命中时事务内重读回填金额改键 + `LogicalTransactions.link` 新旧键。
   - `announceCapture` 对 isRefund 直接 postRefundNotification；`tryShowConfirmCard` 对 isRefund 返回 false。
   - `absorbedByResolved` 前加 `NTF:$dedupKey` 唯一键预检，**仅限退款或无活动 pending 场景**，不得吞掉仍存活的普通 AUTO。
3. 业务/UI 层：
   - `LedgerViewModel`：退款操作统一改调 RefundActions；退役 registerRefund/markRefundAsIncome 路径；保留本地 confirmPending/discardPending 终态接线。
   - `AppNav`：新增 `refundLink/{pendingId}`、`refundLegacy/{refundId}`；保留无参数 refundLink 作安全 fallback。
   - `PendingScreen`：退款待处理条目点击跳 `refundLink/{id}`；旧版 refundPending 收入跳 `refundLegacy/{id}`；移除"记为收入"。
   - `RefundLinkScreen`：按上游重写两种模式 + RefundFilters 候选筛选，UI 组件沿用本地 Material3 风格。
   - `EditTransactionScreen`/`QuickAddScreen`：保存前接 `RefundRules.editError`。
4. 移植 `RefundCaptureTest`、`RefundRulesTest`、`RefundFiltersTest`、`PendingActionsTest`，并补本地回归（普通 AUTO 不被预检吞、无金额→补金额→选支出全链路）。
